第 8 章 · 第二部分 实现

用 Boot + MVC 实现 Web 应用

上一章的页面是死的。这一章让它动起来：控制器把数据交给模板引擎，模板引擎渲染成 HTML；再学会从请求里取数据——查询参数、路径变量、表单提交。

本章工程 ssh_ch8_ex1 Thymeleaf 动态视图 · ex2 一个 @RequestParam · ex3 多个 @RequestParam · ex4 @PathVariable · ex5 商品列表 GET+POST（逐个参数）· ex6 表单直接绑定成对象

8.1 动态视图：Model 与 Thymeleaf

ssh_ch8_ex1/pom.xml比第 7 章多了模板引擎
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-thymeleaf</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-webmvc</artifactId>
</dependency>
ssh_ch8_ex1 · controller/MainController.java
@Controller
public class MainController {

    @RequestMapping("/home")
    public String home(Model page) {              // ← Spring 自动传进来一个 Model
        page.addAttribute("username", "Katy");
        page.addAttribute("color", "red");
        return "home.html";
    }
}
ssh_ch8_ex1 · resources/templates/home.html
<html lang="en" xmlns:th="http://www.thymeleaf.org">   <!-- 声明 th: 命名空间 -->
<body>
<h1>Welcome
    <span th:style="'color:' + ${color}"
          th:text="${username}"></span>!</h1>
</body>
</html>
目录必须是 templates 用了 Thymeleaf 之后，模板文件要放在 src/main/resources/templates/，不是 static/。放错的症状是：浏览器里直接看到 <span th:text="${username}"> 原样输出，或者干脆 404。

8.2 从请求里取数据

方式一：查询参数 @RequestParam

ssh_ch8_ex3两个参数
@RequestMapping("/home")
public String home(
        @RequestParam String name,
        @RequestParam String color,
        Model page) {
    page.addAttribute("username", name);
    page.addAttribute("color", color);
    return "home.html";
}
// 访问：http://localhost:8080/home?name=Katy&color=blue

方式二：路径变量 @PathVariable

ssh_ch8_ex4
@RequestMapping("/home/{color}")            // 花括号占位
public String home(@PathVariable String color, Model page) {
    page.addAttribute("username", "Katy");
    page.addAttribute("color", color);
    return "home.html";
}
// 访问：http://localhost:8080/home/red

8.3 GET 与 POST：一个完整的小应用

ssh_ch8_ex5 是本章第一个像样的应用：一个商品列表页，能查看也能添加。

ssh_ch8_ex5 · controllers/ProductsController.java
@Controller
public class ProductsController {

    private final ProductService productService;

    public ProductsController(ProductService productService) {   // 构造器注入（第 3 章）
        this.productService = productService;
    }

    // @RequestMapping("/products")                    ← 作者留的旧写法注释
    @GetMapping("/products")
    public String viewProducts(Model model) {
        model.addAttribute("products", productService.findAll());
        return "products.html";
    }

    // @RequestMapping(path = "/products", method = RequestMethod.POST)
    @PostMapping("/products")
    public String addProduct(@RequestParam String name,
                             @RequestParam double price,
                             Model model) {
        Product p = new Product();
        p.setName(name);
        p.setPrice(price);
        productService.addProduct(p);

        model.addAttribute("products", productService.findAll());
        return "products.html";
    }
}
ssh_ch8_ex5 · templates/products.html循环 + 表单
<table>
    <tr><th>PRODUCT NAME</th><th>PRODUCT PRICE</th></tr>
    <tr th:each="p: ${products}">             <!-- 相当于 for (Product p : products) -->
        <td th:text="${p.name}"></td>
        <td th:text="${p.price}"></td>
    </tr>
</table>

<form action="/products" method="post">
    Name: <input type="text" name="name"><br />
    Price: <input type="number" step="any" name="price"><br />
    <button type="submit">Add product</button>
</form>
HTML 表单只会发 GET 和 POST 本章只出现这两个方法，是因为浏览器的 <form> 只支持它们。HTTP 还有 PUT、PATCH、DELETE，在第 10 章的 REST 接口里才派得上用场，那里有一张完整的对照表。HTTP 本身不熟的话，先读附录 A。

更省事的写法：直接绑定成对象

ssh_ch8_ex6对比 ex5
@PostMapping("/products")
public String addProduct(Product p, Model model) {    // ← 不再逐个写 @RequestParam
    productService.addProduct(p);
    model.addAttribute("products", productService.findAll());
    return "products.html";
}
它是怎么工作的 Spring 看到一个既不是 Model、也没有任何注解的自定义类型参数，就会：new 一个实例 → 遍历它的 setter → 用同名的请求参数去填。表单里 name="name" 和 name="price" 正好对上 setName / setPrice。
参数一多，这种写法优势就非常明显。真实项目里再配上 @Valid 做校验，就是标准的表单处理方式。
一个小细节 ssh_ch8_ex6 的 Main 写的是 static void main(String[] args)（没有 public），而其他 Boot 工程都是 public static void main。功能一样，Java 25 允许省略 public。仓库里这类不一致有几处，不用纠结。

动手练习

练习 · 把 ex5 改造成 ex6

  1. 运行 ssh_ch8_ex5，添加两个商品，然后按 F5 刷新——浏览器会弹出“确认重新提交表单”。记住这个现象，第 9 章解决它。
  2. 把 ssh_ch8_ex5 的 addProduct 改成 ex6 的对象绑定写法，验证结果一致。
  3. 给 Product 加一个 String category 字段和对应的表单输入框，观察对象绑定自动处理了新字段——而逐个 @RequestParam 的写法需要改方法签名。
  4. 重启应用，发现商品列表空了。想想为什么（提示：ProductService 用的是内存里的 ArrayList，且它是单例 bean）。第 12 章会把它换成数据库。

本章自测

Model 里的数据能活多久？

只在这一次请求内。渲染完成，数据就没了。如果需要跨请求保留（比如登录后记住用户是谁），要用第 9 章的 session 作用域，或者 RedirectAttributes（跨一次重定向）。

@RequestParam 和 @PathVariable 怎么选？

看数据的角色：它是资源标识还是查询修饰。/products/42 里的 42 标识某个商品 → 路径变量；/products?category=book&page=2 里的两个值在筛选结果 → 查询参数。第 10 章做 REST 时这个区分更重要，因为它直接决定 API 设计的好坏。

为什么 @PostMapping 之后刷新会重复提交？

因为浏览器记住的“当前页面”是一次 POST 请求，刷新就是把这次 POST 再发一遍。标准解法是 POST-Redirect-GET：POST 处理完不直接渲染，而是返回 redirect: 让浏览器发起一次新的 GET。ssh_ch9_ex2 的 return "redirect:/main" 就是这个模式。
