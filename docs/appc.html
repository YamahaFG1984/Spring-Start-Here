速查：注解、报错、术语

三张可以随时翻回来查的表。注解表按“它解决什么问题”分组；报错表按“你在控制台里看到的那行字”组织；术语表给出每个词在本手册里的确切含义和首次出现的章节。

C.1 注解速查

把对象放进上下文、连起来（第 2–5 章）

注解标在哪作用章
@Configuration类声明配置类，里面的 @Bean 方法会被代理2、3
@Bean方法把返回值注册成 bean，方法名即 bean 名2
@Component类让组件扫描把这个类注册成 bean2
@Service / @Repository类带语义的 @Component；@Repository 另有异常翻译4、12
@ComponentScan配置类指定去哪些包里找上面这些注解2
@Autowired构造器 / 字段 / setter请 Spring 注入依赖；唯一构造器上可省略3
@Primary类 / @Bean 方法同类型多个 bean 时的默认选择2、4
@Qualifier注入点；也可标在类上当标签同类型多个 bean 时点名要哪个3、4
@PostConstruct方法依赖注入完成后执行一次（jakarta.annotation）2
@Scope类 / @Bean 方法改作用域，最常见是改成原型5
@Lazy类 / @Bean 方法第一次用到时才创建5

切面（第 6 章）

注解标在哪作用
@EnableAspectJAutoProxy配置类开启切面机制。纯 Spring 工程必须写；Boot 工程引入 AOP starter 后自动开启
@Aspect类声明切面。它不会把类变成 bean，还得另外注册
@Around方法包住目标方法，要自己调 proceed() 并返回结果
@Before / @After / @AfterReturning / @AfterThrowing方法在目标方法之前 / 之后 / 正常返回后 / 抛异常后执行
@Order切面类多个切面的嵌套顺序，数字小的在外层

Web（第 7–11 章）

注解标在哪作用章
@SpringBootApplication主类配置类 + 组件扫描 + 自动配置7
@Controller类方法返回值是视图名7
@RestController类方法返回值直接写进响应体10
@ResponseBody方法单个方法的返回值写进响应体10
@RequestMapping类 / 方法映射路径，可限定 HTTP 方法7、8
@GetMapping / @PostMapping方法限定了方法的 @RequestMapping；另有 Put / Patch / Delete7、8、10
@RequestParam参数取查询参数或表单字段8
@PathVariable参数取路径里的 {变量}8
@RequestBody参数把请求体的 JSON 反序列化成对象10
@RequestHeader参数取请求头11
@RestControllerAdvice + @ExceptionHandler类 + 方法全局把异常映射成 HTTP 响应10
@RequestScope / @SessionScope / @ApplicationScope类每请求 / 每会话 / 全应用一个实例9
@Value字段 / 参数注入配置属性，${key:默认值}7、11、12
@EnableFeignClients + @FeignClient主类 + 接口声明式 HTTP 客户端11

数据与事务（第 12–14 章）

注解标在哪作用章
@TransactionalService 的方法或类方法在一个事务里执行，抛非受检异常则回滚13
@Id实体字段主键。用 org.springframework.data.annotation.Id14
@QueryRepository 方法手写 SQL，:name 对应同名参数14
@ModifyingRepository 方法声明 @Query 是写操作。UPDATE / DELETE / INSERT 必须加14

测试（第 15–16 章）

注解来自作用章
@Test / @BeforeEach / @DisplayNameJUnit 5测试方法 / 每个测试前执行 / 报告里显示的名字15

@Mock / @InjectMocksMockito造替身 / 造被测对象并把替身注进去15

C.2 常见报错速查

在控制台输出里搜下面第一列的关键词。Spring 的堆栈很长，从下往上找最后一个 Caused by:，那一行通常才是真正的原因。

启动阶段

你看到的原因怎么办章
找不到 main 方法 / main 相关的编译错误第 2–6 章的 static void main() 需要 JDK 25升级 JDK，或改回 public static void main(String[] args)1、2
NoSuchBeanDefinitionException要的类型在上下文里一个都没有：类上忘了加注解、不在扫描范围内、或者 @Bean 方法没写检查注解和 @ComponentScan 的包；Boot 工程检查类是否在主类所在包之下2、7
NoUniqueBeanDefinitionException要的类型有多个 bean，Spring 不知道选谁@Primary、@Qualifier，或按名字取2、3、4
UnsatisfiedDependencyException创建某个 bean 时它的依赖解决不了。这是一层包装看它的 Caused by，里面多半是上面两个之一3
BeanCurrentlyInCreationException循环依赖重新设计依赖方向，见第 3 章 3.4 节3
Boot 启动时提示 The dependencies of some of the beans in the application context form a cycle同上。Boot 工程连字段注入的环也禁止同上3
Port 8080 was already in use另一个应用占着端口，常见于上一个示例没关关掉它，或加 server.port=90907、11
Failed to configure a DataSource / Failed to determine a suitable driver class引入了 JDBC starter，但 classpath 上没有数据库驱动，也没配 spring.datasource.url加上 H2 或 MySQL 驱动依赖，或补全连接配置12
Communications link failure连不上 MySQL：没启动、端口不对只有 ssh_ch12_ex2 / ex3 会遇到，见附录 D12
提示无法解析占位符 ${…}@Value 引用的属性没配，也没给默认值在 application.properties 里补上，或写成 ${key:默认值}7

请求阶段

你看到的原因怎么办章
404，或一个写着 Whitelabel Error Page 的页面路径没匹配到任何控制器方法；控制器类不在扫描范围内；模板或静态文件放错了目录核对路径拼写；确认类在主类包下；静态页放 static/，Thymeleaf 模板放 templates/7、8
页面上原样显示 ${username}模板没经过 Thymeleaf：文件放在了 static/，或缺 Thymeleaf starter挪到 templates/8
405 Method Not Allowed路径对了但 HTTP 方法不对核对 @GetMapping / @PostMapping 和你发的方法8、10
415 Unsupported Media TypePOST JSON 时没带 Content-Type: application/json补上请求头10
400，日志里有 HttpMessageNotReadableException请求体不是合法 JSON，或类型对不上检查引号、逗号；见附录 A10
400，提示缺少必需的请求参数@RequestParam 默认必填，而请求里没有补上参数，或声明 required = false8、9
调用方报 ResourceAccessException / Connection refused被调用的服务没启动或地址不对第 11 章要先启动 ssh_ch11_payments11
EmptyResultDataAccessExceptionjdbc.queryForObject() 期望恰好一行，结果查到零行先确认数据存在；或改用返回 Optional 的写法13、14
Method is only allowed for a querySpring Data 的 @Query 写了 UPDATE / DELETE 却没加 @Modifying加上 @Modifying14

不报错，但行为不对

现象先查这几样章
切面没有执行① 切面类是不是 bean；② 纯 Spring 工程有没有 @EnableAspectJAutoProxy；③ 切点表达式的包名对不对；④ 是不是同一个类内部的自调用6
事务没有回滚① 抛的是不是受检异常；② 异常是不是被自己 catch 了；③ 是不是自调用；④ 方法是不是 private13
原型 bean 每次拿到的是同一个它是不是被注入进了一个单例5
不同用户的数据串了单例 bean 里是不是有可变的实例字段5、9
被拦截的方法返回了 null@Around 通知有没有把 proceed() 的结果 return 出去6
JSON 里少了某个字段那个字段有没有 getter10
@InjectMocks 的对象里依赖是 nullmock 的类型和被测类的构造器参数对不对得上15
照书写的 @MockBean、javax.* 编译不过见首页“最容易被绊倒的四处”首页

C.3 术语表

术语含义章
上下文 / 容器
Context / IoC container		Spring 管理的那一池对象，以及管理它们的那个对象（ApplicationContext）。两个词在本手册里同义1、2
bean引用被上下文持有的对象。不是一种特殊的类2
控制反转 IoC对象的创建和组装由框架决定，而不是由你的代码决定1
依赖注入 DIIoC 的具体做法：一个对象需要的其他对象由容器递给它3
装配 Wiring在 bean 之间建立引用关系的过程3
构造型注解 Stereotype@Component 及其变体 @Service、@Repository、@Controller2、4
作用域 Scope决定一个 bean 有几个实例、活多久5、9
饥饿 / 懒 初始化上下文启动时就创建 / 第一次用到才创建5
代理 ProxySpring 生成的、包在你的对象外面的对象，用来在方法调用前后插入逻辑。AOP、事务、web 作用域都靠它3、6、9、13
切面、通知、切点、连接点、织入见第 6 章 6.1 节的术语表6
横切关注点日志、事务、鉴权这类散布在许多业务方法里、又与业务本身无关的逻辑6
starterBoot 提供的依赖包，把做某件事需要的一组库打包成一个依赖7
自动配置Boot 根据 classpath 上有什么、你配了什么，自动注册相应的 bean7、12
Servlet 容器负责监听端口、解析 HTTP、把请求交给应用的服务器程序。本仓库用内嵌的 Tomcat7
DispatcherServletSpring MVC 的总入口，把每个请求分发给对应的控制器方法7
视图 / 模板服务端渲染成 HTML 的文件。本仓库用 Thymeleaf8
端点 Endpoint一个“HTTP 方法 + 路径”的组合，对应一个控制器方法10
序列化 / 反序列化Java 对象转成 JSON / JSON 转成 Java 对象10
DTO只用来在层与层、服务与服务之间传数据的对象，没有业务逻辑。PaymentDetails、TransferRequest 都是10、13
幂等同一个请求执行一次和执行多次，最终状态相同10
契约先行先写 API 描述文件（OpenAPI），再由它生成代码10
阻塞 / 非阻塞等待 I/O 时线程是停下来等，还是先去做别的11
数据源 DataSource提供数据库连接的对象，通常背后是一个连接池12
连接池预先建好并反复复用的一批数据库连接。Boot 默认用 HikariCP12
事务一组要么全部成功、要么全部撤销的数据库操作13
提交 / 回滚让事务里的修改生效 / 全部撤销13
传播行为 Propagation一个事务方法调用另一个事务方法时，是加入现有事务还是另开一个13
受检 / 非受检异常必须声明或捕获的异常（Exception 的子类）/ 不必声明的异常（RuntimeException 的子类）。事务默认只对后者回滚13
派生查询Spring Data 根据方法名（如 findByName）自动生成的查询14
被测单元 SUT一个测试里唯一用真实实现的那个类15
替身 / mock代替真实依赖的假对象，行为由测试指定，并能记录自己被怎样调用15
单元测试 / 集成测试只测一个类、不启动 Spring / 启动上下文、测多个部件装在一起的行为15、16
