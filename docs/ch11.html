消费 REST 端点

上一章你的应用是服务端。这一章反过来：你的应用去调别人的 REST 接口。Spring 提供了四种客户端，仓库把它们全演示了一遍——包括书里没有的 RestClient，它现在是官方推荐的默认选择。

本章工程 ssh_ch11_payments 被调用的服务端（要先启动它）· ex1 RestClient （书中没有）· ex2 OpenFeign · ex3 RestTemplate · ex4 WebClient

11.1 实验场景

ssh_ch11_payments · PaymentsController.java服务端
@PostMapping("/payment")
public ResponseEntity<Payment> createPayment(
        @RequestHeader String requestId,          // 从请求头取值
        @RequestBody Payment payment) {

    logger.info("Received request with ID " + requestId
                + " ;Payment Amount: " + payment.getAmount());

    payment.setId(UUID.randomUUID().toString());

    return ResponseEntity.status(HttpStatus.OK)
            .header("requestId", requestId)
            .body(payment);
}

11.2 RestClient —— 现在的首选（书中没有）

ssh_ch11_ex1 · proxies/PaymentsProxy.java
@Component
public class PaymentsProxy {

    private final RestClient restClient;

    public PaymentsProxy(@Value("${payments.url:http://localhost:8080}") String paymentsUrl) {
        this.restClient = RestClient.create(paymentsUrl);
    }

    public Payment createPayment(String requestId, Payment payment) {
        return restClient.post()
                .uri("/payment")
                .header("requestId", requestId)
                .body(payment)
                .retrieve()
                .body(Payment.class);
    }
}
RestClient 是什么 Spring Framework 6.1 新增的同步 HTTP 客户端。它把 WebClient 的流式 API 搬到了阻塞世界：写法像 WebClient 一样现代，行为像 RestTemplate 一样简单（同步、直接返回结果）。
Spring 官方现在的建议是：新代码用 RestClient；RestTemplate 进入维护模式（不再加新特性）；只有真的需要响应式栈时才用 WebClient。
书是 2021 年写的，那时 RestClient 还不存在——这是本章和书差别最大的地方。

11.4 RestTemplate —— 老将，维护模式

ssh_ch11_ex3 · proxies/PaymentsProxy.java
@Component
public class PaymentsProxy {

    private final RestTemplate rest;

    @Value("${payments.url:http://localhost:8080}")
    private String paymentsUrl;

    public PaymentsProxy() {
        this.rest = new RestTemplate();
    }

    public Payment createPayment(String requestId, Payment payment) {
        String url = paymentsUrl + "/payment";

        HttpHeaders headers = new HttpHeaders();
        headers.add("requestId", requestId);

        HttpEntity<Payment> httpEntity = new HttpEntity<>(payment, headers);

        return rest.postForObject(url, httpEntity, Payment.class);
    }
}
书中的 RestTemplate 写法
public PaymentsProxy(RestTemplate rest) {
  this.rest = rest;         // 注入 bean
}

ResponseEntity<Payment> response =
  rest.exchange(uri,
      HttpMethod.POST,
      httpEntity,
      Payment.class);
return response.getBody();
仓库的写法
public PaymentsProxy() {
  this.rest = new RestTemplate();   // 直接 new
}

return rest.postForObject(url,
                          httpEntity,
                          Payment.class);
两点差异：① 书里把 RestTemplate 注册成 bean 再注入（更规范，方便统一配置超时、拦截器）；仓库直接 new（更简单，但每个 proxy 一个实例）。生产代码建议用 RestTemplateBuilder 建 bean。② postForObject() 比 exchange() 简洁，但拿不到状态码和响应头；需要它们时还得用 exchange()。

11.5 WebClient —— 响应式

ssh_ch11_ex4 · proxies/PaymentsProxy.java
@Component
public class PaymentsProxy {

    private final WebClient webClient;

    public PaymentsProxy(@Value("${payments.url:http://localhost:8080}") String paymentsUrl) {
        this.webClient = WebClient.create(paymentsUrl);
    }

    public Payment createPayment(String requestId, Payment payment) {
        return webClient.post()
                .uri("/payment")
                .header("requestId", requestId)
                .bodyValue(payment)
                .retrieve()
                .bodyToMono(Payment.class)
                .block();                    // ← 注意这里
    }
}
.block() 把响应式的好处全抵消了 WebClient 的价值在于非阻塞：发出请求后线程立刻去干别的，响应回来时再回调。而 .block() 让当前线程停在这里等——等于用响应式 API 做同步调用，白白背上了响应式的复杂度。
在传统 Spring MVC 应用里需要同步调用，请用 RestClient（ex1），不要用 WebClient + block。WebClient 应该配合 WebFlux 使用，整条链路返回 Mono/Flux。

动手练习

动手 · 跑通两端

# 终端 1：先启动被调用方（端口 8080）
cd ssh_ch11_payments && ./mvnw spring-boot:run

# 终端 2：启动调用方（端口 9090）
cd ssh_ch11_ex1 && ./mvnw spring-boot:run

# 终端 3：打到调用方，它会转发给 8080
curl -i -X POST http://localhost:9090/payment \
     -H "Content-Type: application/json" -d '{"amount":100.0}'
  1. 观察终端 1 的日志，能看到 Received request with ID …——说明请求头透传成功了。
  2. 把 ex1 换成 ex2、ex3、ex4 再各跑一遍，curl 命令和结果完全一致。这正是本章想说明的：客户端选型不影响外部行为，只影响你的代码长什么样。
  3. ssh_ch11_ex4 没有配 server.port，默认也是 8080，会和 payments 服务端口冲突。跑它之前先给它的 application.properties 加上 server.port=9090。
  4. 把 payments 服务停掉，再调用一次，观察四种客户端各自抛出什么异常——这是理解它们错误处理差异的最快方式。

本章自测

为什么 Spring 官方说 RestTemplate 进入了“维护模式”？

因为它的 API 设计于 2009 年，方法重载多达几十个（getForObject/getForEntity/exchange/execute…），难以扩展也难记。Spring 5 先用 WebClient 提供了现代 API，但它是响应式的，逼着同步应用引入响应式依赖；Spring 6.1 于是推出 RestClient——WebClient 的流式 API + 同步语义。RestTemplate 不会被删除，但也不会有新特性了。

OpenFeign 相比 RestClient 的独特价值是什么？

它是声明式的：你只描述“调什么”，不写“怎么调”。在微服务体系里，它还能和 Spring Cloud 的服务发现（用服务名代替 URL）、负载均衡、熔断降级无缝集成。代价是多一个 Spring Cloud 依赖，以及一层抽象带来的调试成本。单体应用调几个外部 API，RestClient 更轻；微服务集群内部互调，Feign 更省事。

在 Spring MVC 应用里用 WebClient.block() 有什么问题？

你付出了响应式的全部成本（新的 API 心智、更难读的堆栈、额外依赖），却没拿到它唯一的好处（线程不被占用）。更糟的是，在某些线程配置下 block() 会直接抛 IllegalStateException（不允许在响应式线程里阻塞）。要同步就用 RestClient——它是专门为这个场景造的。
