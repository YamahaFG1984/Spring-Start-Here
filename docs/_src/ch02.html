Spring 上下文：定义 bean

上下文（context）是 Spring 的核心数据结构：一块由框架管理的对象池。你要做的第一件事，就是学会用三种方式往里面放东西——因为只有进了池子的对象，Spring 才能对它做任何事。

2.1 先把工程建起来

第 2–6 章都是纯 Spring Core 工程，没有 Spring Boot。这是作者刻意的安排：先让你手工创建上下文，看清它是个普通 Java 对象，之后 Boot 的“魔法”才不神秘。

上下文长什么样

ssh_ch2_ex1/src/main/java/com/example/Main.java
public class Main {
    static void main() {

2.2 方式一：@Bean 方法

ssh_ch2_ex2 · config/ProjectConfig.java
@Configuration
public class ProjectConfig {

    @Bean
    Parrot parrot() {          // ← 方法名就是 bean 的名字
        var p = new Parrot();
        p.setName("Koko");
        return p;
    }

    @Bean
    String hello() { return "Hello"; }   // 任何类型都能当 bean

    @Bean
    Integer ten() { return 10; }
}
ssh_ch2_ex2 · Main.java
var context = new AnnotationConfigApplicationContext(ProjectConfig.class);

Parrot p = context.getBean(Parrot.class);   // 按类型取
System.out.println(p.getName());            // Koko
System.out.println(context.getBean(String.class));   // Hello
System.out.println(context.getBean(Integer.class));  // 10

三条规则，记住就够用：

  1. @Configuration 标记“这是一个配置类”，把它传给 AnnotationConfigApplicationContext 的构造器。
  2. 方法上的 @Bean 表示“把返回值放进上下文”。方法只在容器启动时被调一次（单例，见第 5 章）。
  3. 方法名 = bean 名。也可以写 @Bean(name = "miki") 覆盖。
可以放任何类型 String 和 Integer 也能当 bean。这不是玩笑——第 12 章的 DataSource、第 6 章的切面对象，本质上都是这样注册进去的。

2.3 方式二：构造型注解（@Component）

@Bean 的问题是：每加一个 bean 就要写一个方法。对自己写的类，更省事的方式是直接标注类本身，然后让 Spring 扫描。

ssh_ch2_ex5 · beans/Parrot.java
@Component
public class Parrot {

    private String name;

    @PostConstruct
    void init() {
        System.out.println("Parrot initialized");
        this.name = "Koko";
    }
    // getter / setter ...
}
ssh_ch2_ex5 · config/ProjectConfig.java
@Configuration
@ComponentScan(basePackages = "com.example.beans")   // 去哪儿找 @Component
public class ProjectConfig { }
书中 · import
import javax.annotation.PostConstruct;

<!-- 还要单独加依赖 -->
javax.annotation-api 1.3.2
仓库 · import
import jakarta.annotation.PostConstruct;

<!-- 依赖也换名字了 -->
jakarta.annotation-api 2.1.1
为什么变：Java EE 更名为 Jakarta EE 后，包名从 javax.* 改成 jakarta.*。Spring 6 起只认 jakarta.*。你在书上看到的每一个 javax. import，在这个仓库里都要换成 jakarta.——这是全书最高频的一处差异。

@Bean 和 @Component 该用哪个

@Bean@Component
控制粒度完全控制实例的创建过程Spring 调无参/唯一构造器
同类型多实例可以（写多个方法）一个类只能有一个
能否用于第三方类可以（你不能改别人的源码去加注解）不行
代码量每个 bean 一个方法一个注解
初始化后逻辑写在方法体里用 @PostConstruct
实战选择 自己写的类用 @Component（及第 4 章的 @Service/@Repository）；第三方类（DataSource、RestClient、切面对象）用 @Bean。仓库里第 12 章的 ssh_ch12_ex3 就是典型的 @Bean 用法。

2.4 方式三：编程式注册

前两种方式都是“启动时按配置注册”。如果 bean 要不要注册取决于运行时条件，就需要第三种。

ssh_ch2_ex6 · Main.java
var context = new AnnotationConfigApplicationContext(ProjectConfig.class);

Parrot x = new Parrot();
x.setName("Koko");

Supplier<Parrot> parrotSupplier = () -> x;      // 提供实例的工厂

context.registerBean("parrot1", Parrot.class, parrotSupplier);

Parrot p = context.getBean(Parrot.class);
System.out.println(p.getName());   // Koko

registerBean() 的四个参数：bean 名字、类型、Supplier（怎么造出这个实例）、以及可选的若干 BeanDefinitionCustomizer（比如 bd -> bd.setPrimary(true)）。

什么时候真的会用到 比如“只有配置里开启了某个开关才注册这个 bean”。不过现代 Spring 里更常见的做法是 @Conditional 系列注解（Boot 的自动配置大量使用），registerBean 属于兜底手段，了解即可。

本章自测

@Bean 方法会被调用几次？

默认作用域是单例，所以整个上下文生命周期内只调用一次，返回值被缓存起来。第 5 章会看到把它改成 @Scope(BeanDefinition.SCOPE_PROTOTYPE) 后，每次 getBean 都会重新调用。这个细节也是第 3 章“方法直接调用能装配 bean”能成立的原因。

bean 的名字默认是什么？

@Bean 方式取方法名；@Component 方式取类名首字母小写（CommentService → commentService）。两者都可以显式指定：@Bean("miki") / @Component("miki")。名字在第 3 章配合 @Qualifier 时会变得重要。

为什么 @PostConstruct 需要额外加依赖？

因为它不属于 Spring，而是 Jakarta Annotations 规范的一部分。Java 11 之前这些注解在 JDK 里，之后被移出，所以要显式加 jakarta.annotation-api（书里是 javax.annotation-api）。仓库里只有 ssh_ch2_ex5 加了这个依赖，因为只有它用到。
