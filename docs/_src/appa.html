A.1 HTTP 是什么

HTTP 是浏览器（或任何客户端）和服务器之间的对话规则。规则只有一条主线：客户端发一个请求，服务器回一个响应，一问一答，服务器从不主动开口。请求和响应都是纯文本，结构也一样：一行起始行、若干行头、一个空行、可选的正文。

一次完整的对话启动 ssh_ch10_ex7 后执行 curl -v 看到的内容（有删节）
$ curl -v -X POST http://localhost:8080/payment \
       -H "Content-Type: application/json" -d '{"amount":1000.0}'

A.4 HTTP 是无状态的，那登录是怎么记住的

协议本身不记得上一次请求是谁发的，每个请求都是独立的。第 9 章的“登录后记住用户”靠的是在这之上加的一层约定：

  1. 第一次请求时，服务器创建一个会话，并在响应里带一个头 Set-Cookie: JSESSIONID=…。
  2. 浏览器记下这个 cookie，之后对同一网站的每个请求都自动带上 Cookie: JSESSIONID=…。
  3. 服务器凭这个 ID 找到对应的会话，@SessionScope 的 bean 就存在里面。

这也解释了第 9 章练习里“换一个浏览器就要重新登录”：另一个浏览器没有那个 cookie。用 curl 测第 9 章的工程时，要加 -c cookies.txt -b cookies.txt 让它像浏览器一样保存并回传 cookie。

A.5 JSON：十分钟学会

JSON 是一种表示数据的文本格式，REST 接口的请求体和响应体几乎都用它。语法只有两种结构和四种基本值：

一个覆盖全部语法的例子
{
  "id": 1,
  "name": "Helen Down",
  "amount": 1000.50,
  "active": true,
  "nickname": null,
  "tags": ["vip", "early-user"],
  "address": { "city": "Paris", "zip": "75001" }
}
JSON写法对应的 Java 类型
对象{ "键": 值, … }一个有 getter/setter 的类，或 Map
数组[ 值, 值, … ]List、数组
字符串"text"String，以及日期、枚举等
数字42、3.14int、long、double、BigDecimal
布尔true / falseboolean
空nullnull
手写 JSON 最常犯的四个错 ① 键必须用双引号，{name: "x"} 和 {'name': 'x'} 都不合法。
② 最后一个元素后面不能有逗号。
③ 不支持注释。
④ 在 shell 里用 curl 发 JSON，整段要用单引号包起来，否则里面的双引号会被 shell 吃掉。
这四种错服务端都会回 400，日志里是 HttpMessageNotReadableException。

Java 对象和 JSON 是怎么互相变的

Spring 把这件事交给 Jackson。规则在第 10 章讲过，这里并排放一遍：

public class Country {

  public String getName() {…}

JSON

自测

为什么 POST JSON 时不写 Content-Type 会得到 415？

curl 的 -d 默认把 Content-Type 设成 application/x-www-form-urlencoded（表单格式）。Spring 看到 @RequestBody 要一个对象，去找“能把表单格式读成这个对象”的转换器，找不到，于是回答 415：你发的这种媒体类型我处理不了。

400 和 500 都是“出错了”，客户端该怎么区别对待？

收到 4xx 说明请求本身有问题，原样重试没有意义，应该修正请求或把错误提示给用户。收到 5xx 说明服务端出了故障，请求本身可能没错，可以稍后重试（前提是接口幂等，见第 10 章）。

JSON 里的数字 1000.0 到了 Java 里会不会丢精度？

取决于你用什么类型接。字段声明成 double 就按浮点数解析，有精度问题；声明成 BigDecimal，Jackson 会按十进制精确解析。这就是第 12–14 章金额字段都用 BigDecimal 的原因。
