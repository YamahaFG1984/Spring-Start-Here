第 9 章 · 第二部分 实现

使用 Spring Web 作用域

第 5 章说“单例 bean 不能有状态”，但登录这类功能天生就需要状态。Spring 的答案不是让你去写 synchronized，而是提供三种 web 专属作用域——让每个请求、每个用户会话各拿一份自己的实例。

本章工程 ssh_ch9_ex1 @RequestScope 登录 · ex2 加上 @SessionScope 记住登录状态 · ex3 再加 @ApplicationScope 统计全局登录次数

9.1 三种作用域，一张图看懂

作用域注解实例数销毁时机典型用途
request@RequestScope每次 HTTP 请求一个响应发出后接收表单数据、请求级临时状态
session@SessionScope每个用户会话一个会话超时或失效登录用户信息、购物车
application@ApplicationScope整个应用一个应用关闭全局计数、缓存（要考虑并发）

9.2 request 作用域：接住这次请求的数据

ssh_ch9_ex1 · processors/LoginProcessor.java
@Component
@RequestScope                     // ← 关键
public class LoginProcessor {

    private String username;      // 有状态字段——因为是 request 作用域，所以安全
    private String password;

    public boolean login() {
        return "natalie".equals(username) && "password".equals(password);
    }
    // getter / setter ...
}
ssh_ch9_ex1 · controllers/LoginController.java
@Controller
public class LoginController {

    private final LoginProcessor loginProcessor;

    public LoginController(LoginProcessor loginProcessor) { ... }

    @GetMapping("/")
    public String loginGet() { return "login.html"; }

    @PostMapping("/")
    public String loginPost(@RequestParam String username,
                            @RequestParam String password,
                            Model model) {
        loginProcessor.setUsername(username);
        loginProcessor.setPassword(password);
        boolean loggedIn = loginProcessor.login();

        model.addAttribute("message", loggedIn ? "You are now logged in." : "Login failed!");
        return "login.html";
    }
}
这里藏着第 5 章的知识点 LoginController 是单例，LoginProcessor 是request 作用域——按第 5 章的结论，单例注入短作用域 bean 应该会“失效”才对。
它没失效，是因为 Spring 给 web 作用域的 bean 自动加了作用域代理：注入进 Controller 的那个引用其实是一个代理对象，每次方法调用时它去查“当前线程绑定的请求里那个真实实例”，再转发过去。所以你写起来像普通字段，行为却是每请求一份。

9.3 session 作用域：记住登录状态

ssh_ch9_ex2 · services/LoggedUserManagementService.java
@Service
@SessionScope                     // 一个用户会话一个实例
public class LoggedUserManagementService {
    private String username;
    public String getUsername() { return username; }
    public void setUsername(String username) { this.username = username; }
}
ssh_ch9_ex2 · LoginProcessor 登录成功时写入 session
@Component
@RequestScope
public class LoginProcessor {

    private final LoggedUserManagementService loggedUserManagementService;   // session 作用域
    private String username;
    private String password;

    public boolean login() {
        boolean loginResult = false;
        if ("natalie".equals(username) && "password".equals(password)) {
            loginResult = true;
            loggedUserManagementService.setUsername(username);    // ← 存进 session
        }
        return loginResult;
    }
}
ssh_ch9_ex2 · MainController.java受保护页面 + 登出
@GetMapping("/main")
public String home(@RequestParam(required = false) String logout, Model model) {
    if (logout != null) {
        loggedUserManagementService.setUsername(null);      // 登出 = 清空 session 里的用户名
    }

    String username = loggedUserManagementService.getUsername();
    if (username == null) {
        return "redirect:/";                                // 没登录，踢回登录页
    }

    model.addAttribute("username", username);
    return "main.html";
}
这不是真正的安全 书里也强调了：这是教学示例，不是可用的认证方案。密码明文比较、没有防 CSRF、没有会话固定攻击防护、没有密码加密存储。真实项目请用 Spring Security（作者另有一本 Spring Security in Action 讲这个）。

9.4 application 作用域：全应用共享

ssh_ch9_ex3 · services/LoginCountService.java
@Service
@ApplicationScope
public class LoginCountService {
    private int count;
    public void increment() { count++; }
    public int getCount() { return count; }
}
这段代码有并发 bug count++ 不是原子操作（读→加→写三步）。两个线程同时登录，可能都读到 17、都写回 18，丢掉一次计数。application 作用域的 bean 和单例 bean 面临完全相同的线程安全问题。
修法：把 int 换成 AtomicInteger，或给方法加 synchronized。 
private final AtomicInteger count = new AtomicInteger();
public void increment() { count.incrementAndGet(); }
public int getCount()   { return count.get(); }

书里明确建议：这种全局共享状态，其实更应该放到数据库里——多实例部署时内存计数本来就不对。

动手练习

练习 · 亲手验证作用域边界

  1. 启动 ssh_ch9_ex2，用 natalie / password 登录，能看到欢迎页。
  2. 换一个浏览器（或用无痕窗口）访问 /main——会被重定向回登录页。这证明 session 作用域的 bean 是按会话隔离的。
  3. 在 ssh_ch9_ex3 里用两个浏览器各登录几次，观察 loginCount 是累加的全局值——application 作用域跨会话共享。
  4. 把 ssh_ch9_ex1 的 LoginProcessor 上的 @RequestScope 删掉（变成单例），然后用两个浏览器同时提交不同用户名。你会看到状态串了。这就是第 5 章那条“单例不能有状态”规则的实战演示。

本章自测

为什么单例 Controller 能安全地持有 request 作用域的 bean？

因为注入的不是真实实例，而是作用域代理（图 9-2）。代理在每次方法调用时，从当前线程绑定的 RequestAttributes 里取出属于本次请求的真实实例再转发。这样单例的字段是固定的（指向代理），而实际干活的对象是每请求一份。

session 作用域的 bean 存在哪里？

存在 Servlet 的 HttpSession 里，Spring 只是替你管理键名和生命周期。这意味着：① 它受 server.servlet.session.timeout 控制；② 多实例部署时会出问题——用户下一次请求可能打到另一台机器，那台机器上没有这个 session。生产环境要么开启会话粘性，要么用 Spring Session 把会话放到 Redis。

什么时候该用 application 作用域，什么时候该用数据库？

判断标准是：这个数据丢了要紧吗、需要跨实例一致吗。缓存、限流计数器这类“丢了可重建、每实例一份也能接受”的，用 application 作用域没问题。像本章的“登录总次数”这种业务统计数据，应用一重启就归零、多实例还各算各的，正确做法是入库。
