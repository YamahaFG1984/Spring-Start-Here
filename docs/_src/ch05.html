Bean 作用域与生命周期

Spring 什么时候造这个对象？造几个？什么时候销毁？这三个问题的答案由作用域决定。本章只讲两个基础作用域（单例、原型），但要把最容易出事的那个组合——单例里注入原型——讲透。

本章工程 ssh_ch5_ex1 单例：同名 bean 同实例 · ex2 两个 service 共享同一个 repository · ex3 饥饿初始化 · ex4 @Lazy · ex5 @Bean + 原型 · ex6 @Component + 原型 · ex7 原型的正确用法 · ex8 原型的错误用法

5.1 单例：默认，也是最常用的

ssh_ch5_ex1
@Bean
public CommentService commentService() { return new CommentService(); }

// Main
var cs1 = c.getBean("commentService", CommentService.class);
var cs2 = c.getBean("commentService", CommentService.class);
System.out.println(cs1 == cs2);   // true
“单例”这个词在 Spring 里被重新定义了 设计模式里的单例是“一个类只有一个实例”。Spring 的单例是“一个 bean 名字只有一个实例”。所以第 2 章 ssh_ch2_ex3 里三个 Parrot bean 全是单例作用域——同一个类，三个实例，各自唯一。这个区别不搞清楚，后面读文档会一直别扭。

被多处注入时，拿到的是同一个

ssh_ch5_ex2
@Repository public class CommentRepository { }

@Service public class CommentService { @Autowired private CommentRepository commentRepository; ... }
@Service public class UserService    { @Autowired private CommentRepository commentRepository; ... }

// Main
boolean b1 = commentService.getCommentRepository() == userService.getCommentRepository();
System.out.println(b1);   // true —— 两个 service 共享同一个 repository 实例
单例 bean 必须是无状态的 既然一个实例被全应用共享、还会被多个 HTTP 线程同时调用，那么在单例 bean 里放可变字段就是并发 bug。这是 Spring 应用里最常见的生产事故之一。
方法内的局部变量没问题（每个线程有自己的栈），有问题的是private 实例字段。第 9 章的 web 作用域就是为了给“确实需要状态”的场景提供正确出路。

饥饿 vs 懒加载

ssh_ch5_ex3默认：饥饿（eager）
@Service
public class CommentService {
    public CommentService() { System.out.println("CommentService instance created!"); }

// Main 里只创建上下文，什么都不取

ssh_ch5_ex4加 @Lazy 后

5.2 原型：每次要都给新的

ssh_ch5_ex5
@Bean
@Scope(BeanDefinition.SCOPE_PROTOTYPE)
public CommentService commentService() { return new CommentService(); }

// Main
var cs1 = c.getBean("commentService", CommentService.class);
var cs2 = c.getBean("commentService", CommentService.class);
System.out.println(cs1 == cs2);   // false —— 两个不同实例
书中
import org.springframework.beans
   .factory.config
   .ConfigurableBeanFactory;

@Scope(ConfigurableBeanFactory
       .SCOPE_PROTOTYPE)
仓库
import org.springframework.beans
   .factory.config
   .BeanDefinition;

@Scope(BeanDefinition
       .SCOPE_PROTOTYPE)
为什么变：两个常量的值都是字符串 "prototype"，功能完全等价。BeanDefinition 是更贴近“bean 定义”这个概念的位置，也是现在 Spring 文档使用的写法。你也可以直接写 @Scope("prototype")，三者没有任何差别。

原型 bean 的正确用法

ssh_ch5_ex7 和 ex8 是本章最重要的一对对照。场景是：CommentProcessor 处理评论时需要把评论存在自己的字段里，所以它有状态，必须是原型。

两个工程共用的 CommentProcessor
@Component
@Scope(BeanDefinition.SCOPE_PROTOTYPE)
public class CommentProcessor {

    @Autowired private CommentRepository commentRepository;

    private Comment comment;                        // ← 有状态！所以必须是原型

    public void setComment(Comment comment) { this.comment = comment; }
    public void processComment() { /* 修改 comment */ }
    public void validateComment() { /* 校验 comment */ }
}
✓ ssh_ch5_ex7 · 正确
@Service
public class CommentService {

  @Autowired
  private ApplicationContext context;

  public void sendComment(Comment comment) {
    CommentProcessor p =
      context.getBean(CommentProcessor.class);
    p.setComment(comment);
    p.processComment();
  }
}

每次调用都从上下文现取一个新的 processor。

✗ ssh_ch5_ex8 · 错误
@Service
public class CommentService {

  @Autowired
  private CommentProcessor commentProcessor;

  public void sendComment(Comment comment) {
    commentProcessor.setComment(comment);
    commentProcessor.processComment();
  }
}

注入一次就固定了，所有调用共享同一个 processor。

比 ApplicationContext 更优雅的写法 ssh_ch5_ex7 注入 ApplicationContext 是书里的教学写法，缺点是业务代码依赖了容器 API。生产中更常用这两种： 
// 方式一：注入工厂（Spring 4.3+，推荐）
private final ObjectProvider<CommentProcessor> processorProvider;
CommentProcessor p = processorProvider.getObject();

// 方式二：作用域代理，注入点写法不变，实际每次调用转发到新实例
@Component
@Scope(value = BeanDefinition.SCOPE_PROTOTYPE, proxyMode = ScopedProxyMode.TARGET_CLASS)
public class CommentProcessor { ... }

两种作用域速查

singleton（默认）prototype
实例数每个 bean 名字 1 个每次请求一个新的
创建时机上下文启动时（除非 @Lazy）每次 getBean / 注入时
可变字段禁止（并发风险）允许，这正是它存在的理由
销毁回调上下文关闭时调 @PreDestroy不管，交出去就不负责了
典型用途Service / Repository / Controller / 配置持有请求级状态的处理器
使用频率99%1%
原型 bean 没有销毁回调 Spring 把原型实例交给你之后就不再持有引用，所以 @PreDestroy 不会被调用。如果原型 bean 持有需要关闭的资源（连接、文件句柄），必须由使用方自己关。

本章自测

为什么单例 bean 不能有可变字段？

因为在 web 应用里，同一个单例 bean 会被多个 HTTP 请求线程并发调用。实例字段是共享的，一个线程写、另一个线程读，就会读到别人的数据（图 5-3 上半部分演示的正是这个）。方法内的局部变量在各自线程栈上，没有这个问题。真需要请求级状态，用第 9 章的 @RequestScope。

为什么给单例注入原型，原型就“失效”了？

因为依赖注入发生在单例被创建的那一刻，且只发生一次。那一次注入确实向上下文要了一个新的原型实例，但之后单例的字段就一直指着它。要让原型真正每次都新，就必须每次调用时重新去要——ApplicationContext.getBean()、ObjectProvider、或作用域代理，三条路都是在做这件事。

@Scope("prototype")、BeanDefinition.SCOPE_PROTOTYPE、ConfigurableBeanFactory.SCOPE_PROTOTYPE 有区别吗？

没有。三者的值都是字符串 "prototype"。书里用第三种，仓库用第二种，纯粹是写法偏好。用常量而不是裸字符串的好处是防拼写错误。
