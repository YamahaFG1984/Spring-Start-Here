第 12 章 · 第二部分 实现

在 Spring 应用中使用数据源

到目前为止，所有数据一重启就没了。这一章接上数据库。核心概念只有两个：DataSource（管连接的池子）和 JdbcTemplate（帮你把 JDBC 那堆样板代码擦掉的工具）。

本章工程 ssh_ch12_ex1 H2 内存库，开箱即跑 · ex2 换成 MySQL，靠 properties 配置 · ex3 自定义 DataSource bean

12.1 DataSource 是什么

建立一个数据库连接需要 TCP 握手 + 认证，通常要几十毫秒。如果每次查询都新建一个连接，性能会被这一步吃光。所以真实应用都用连接池——预先建好一批连接反复复用。DataSource 就是这个池子的抽象接口。

12.2 用 JdbcTemplate 读写数据

ssh_ch12_ex1 · repositories/PurchaseRepository.java
@Repository
public class PurchaseRepository {

    private final JdbcTemplate jdbc;

    public PurchaseRepository(JdbcTemplate jdbc) {     // Boot 自动配好了这个 bean
        this.jdbc = jdbc;
    }

    public void storePurchase(Purchase purchase) {
        String sql = "INSERT INTO purchase (`product`, `price`) VALUES (?, ?)";
        jdbc.update(sql, purchase.getProduct(), purchase.getPrice());
    }

    public List<Purchase> findAllPurchases() {
        String sql = "SELECT * FROM purchase";

        RowMapper<Purchase> purchaseRowMapper = (r, i) -> {   // 一行 ResultSet → 一个对象
            Purchase rowObject = new Purchase();
            rowObject.setId(r.getInt("id"));
            rowObject.setProduct(r.getString("product"));
            rowObject.setPrice(r.getBigDecimal("price"));
            return rowObject;
        };

        return jdbc.query(sql, purchaseRowMapper);
    }
}
两个核心方法 update(sql, args...) 执行 INSERT/UPDATE/DELETE，返回受影响行数；query(sql, rowMapper, args...) 执行 SELECT，用 RowMapper 把每一行变成对象。
? 占位符不是可选的——它是预编译参数，能杜绝 SQL 注入。永远不要用字符串拼接 SQL。
为什么用 BigDecimal 存价格 Purchase.price 声明成 BigDecimal 而不是 double。金额绝不能用浮点数——0.1 + 0.2 != 0.3。第 13、14 章的 Account.amount 同理。这是书里的一个好习惯，值得照抄。

12.3 三种配置数据源的方式

方式一：什么都不配（ex1）

ssh_ch12_ex1pom + properties 全部内容
<dependency><artifactId>spring-boot-starter-jdbc</artifactId></dependency>
<dependency><artifactId>spring-boot-h2console</artifactId></dependency>
<dependency><groupId>com.h2database</groupId><artifactId>h2</artifactId>
             <scope>runtime</scope></dependency>
spring.application.name=ssh_ch12_ex1
# 就这一行，没有任何数据库配置
这就是自动配置的威力 Boot 发现 classpath 上有 H2 驱动、有 spring-boot-starter-jdbc，而你又没有配置任何 spring.datasource.*，于是推断：“他大概是想要一个内存数据库” → 自动创建一个 H2 内存 DataSource + 一个 JdbcTemplate bean，并执行 schema.sql。
启动后访问 http://localhost:8080/h2-console（JDBC URL 填控制台日志里打印的那个 jdbc:h2:mem:...）就能直接看表里的数据。

方式三：自己定义 DataSource bean（ex3）

ssh_ch12_ex3 · config/ProjectConfig.java
@Configuration
public class ProjectConfig {

    @Value("${custom.datasource.url}")      private String datasourceUrl;
    @Value("${custom.datasource.username}") private String datasourceUsername;
    @Value("${custom.datasource.password}") private String datasourcePassword;

    @Bean
    public DataSource dataSource() {
        HikariDataSource dataSource = new HikariDataSource();
        dataSource.setJdbcUrl(datasourceUrl);
        dataSource.setUsername(datasourceUsername);
        dataSource.setPassword(datasourcePassword);
        dataSource.setConnectionTimeout(1000);      // ← 自己控制池参数
        return dataSource;
    }
}
注意属性名前缀 这里用的是 custom.datasource.* 而不是 spring.datasource.*——故意的。因为一旦你自己定义了 DataSource bean，Boot 的自动配置就会退让（它的条件是“用户没有定义 DataSource 时才创建”），spring.datasource.* 那套属性也就不再被读取。用自定义前缀避免误解。
什么时候真的需要方式三 90% 的情况下方式二（properties）就够了，连接池参数也有对应的 spring.datasource.hikari.* 属性。只有在需要多数据源、动态路由数据源、或用特殊的 DataSource 实现（比如带加密、带审计的包装）时，才需要自己写 @Bean。

本章自测

为什么需要连接池？

建立数据库连接的成本（TCP 握手 + 认证 + 会话初始化）通常是几十毫秒，而一次简单查询可能只要 1 毫秒。不用池的话，绝大部分时间花在建连接上。连接池预先建好一批连接循环复用，把这个成本摊薄到接近零。Spring Boot 默认用 HikariCP，是目前性能最好的 Java 连接池。

JdbcTemplate 这个 bean 是谁创建的？

Boot 的 JdbcTemplateAutoConfiguration。它的条件是“classpath 上有 JdbcTemplate 类、上下文里有且仅有一个 DataSource bean、且用户没有自己定义 JdbcTemplate”。所以你只要引了 spring-boot-starter-jdbc 并且有数据源，就能直接注入它。

什么时候用 H2、什么时候用真实数据库？

H2 内存库适合：本地开发起步、快速演示、以及不涉及数据库方言的集成测试。但不要用 H2 测试依赖特定 SQL 方言的代码——H2 的 SQL 兼容层和真实 MySQL/PostgreSQL 有差异，测试通过了生产照样可能挂。更可靠的做法是用 Testcontainers 在测试时起一个真实的数据库容器。
