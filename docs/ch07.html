第 7 章 · 第二部分 实现

理解 Spring Boot 与 Spring MVC

从这一章起进入第二部分。前六章的容器知识一条都不会作废——只是从现在开始，配置上下文这件事交给 Spring Boot 了。本章的目标是：把“魔法”拆成三件具体的事，然后跑起第一个网页。

本章工程 ssh_ch7_ex1 —— 仓库里第一个 Spring Boot 工程。它也是第一个有 pom.xml 父 POM、mvnw 和 application.properties 的工程。

7.1 一个 web 应用由什么组成

两种 web 应用

返回视图（服务端渲染）返回数据（REST）
响应内容完整 HTML 页面JSON / XML
谁来渲染服务端（Thymeleaf 等模板引擎）客户端（前端框架 / 另一个后端）
注解@Controller，方法返回视图名@RestController，方法返回对象
本书章节第 7、8、9 章第 10、11 章

7.2 Spring Boot 到底做了什么

“魔法”其实只有三件事，拆开看一点也不神秘。

父 POM 与 starter

ssh_ch7_ex1/pom.xml全部内容，就这么点
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>4.0.4</version>
</parent>

<properties>
    <java.version>25</java.version>
</properties>

<dependencies>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-webmvc</artifactId>   <!-- 注意没有版本号 -->
    </dependency>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-webmvc-test</artifactId>
        <scope>test</scope>
    </dependency>
</dependencies>

依赖不写版本号，是因为父 POM 里已经声明了一整套经过兼容性验证的版本。这就是“依赖管理”的价值。

书中 · Boot 2.3.4
spring-boot-starter-web
spring-boot-starter-test

两个“大 starter”，一个把整个 Web 栈全带上，一个把所有测试库全带上。

仓库 · Boot 4.0.4
spring-boot-starter-webmvc
spring-boot-starter-webmvc-test

按技术切分的模块化 starter，各自只带需要的东西。

为什么变：Spring Boot 4 做了一次 starter 大重构。过去 spring-boot-starter-web 含义含糊（到底是 Servlet 栈还是响应式栈？），现在拆成 -webmvc（Servlet/阻塞）和 -webflux（响应式）；测试 starter 也不再是一个巨无霸，而是跟着功能 starter 走（-webmvc-test、-jdbc-test、-data-jdbc-test）。
实际影响：书里所有 spring-boot-starter-web 在本仓库都写作 spring-boot-starter-webmvc。写成旧名字通常也能跑（Boot 4 保留了兼容 artifact），但会带进多余依赖，建议跟仓库保持一致。
版本分布 仓库里的 Boot 版本不是完全统一的：第 7–8 章是 4.0.4/4.0.5，第 9–10、12–13 章是 4.0.6，第 11、14 章是 4.1.0；ssh_ch10_ex5 是唯一一个例外，还停在 3.4.1 + 旧的 spring-boot-starter-web（应该是升级时漏掉的）。这不影响学习，但你如果照着某个工程抄 pom，记得看清楚它是哪一版。

7.3 第一个网页

ssh_ch7_ex1 · Main.java
@SpringBootApplication
public class Main {
    public static void main(String[] args) {
        SpringApplication.run(Main.class, args);
    }
}
@SpringBootApplication = 三个注解 @Configuration（这是个配置类）+ @ComponentScan（扫描当前包及子包）+ @EnableAutoConfiguration（开启自动配置）。
第二点很关键：Boot 工程不用手写 @ComponentScan(basePackages=...)，但你的所有类必须放在 Main 所在包的下面，否则扫不到。这是 Boot 新手第一大坑。
ssh_ch7_ex1 · controllers/MainController.java
@Controller
public class MainController {

    @GetMapping("/home")
    public String home() {
        return "home.html";      // 返回的是视图名，不是响应内容
    }
}
ssh_ch7_ex1 · src/main/resources/static/home.html
<!DOCTYPE html>
<html lang="en">
<head><meta charset="UTF-8"><title>Home Page</title></head>
<body><h1>Welcome!</h1></body>
</html>
static 还是 templates？ 本章页面放在 resources/static/——因为它是静态 HTML，没有任何动态内容。
第 8 章开始用 Thymeleaf 后，页面必须放到 resources/templates/。放错目录会得到 404 或者页面原样输出 ${username}，是极常见的错误。
书中
@RequestMapping("/home")
public String home() { ... }
仓库
@GetMapping("/home")
public String home() { ... }
为什么变：@GetMapping 是 @RequestMapping(method = GET) 的快捷写法（Spring 4.3 引入）。仓库统一用了语义更明确的 @GetMapping/@PostMapping。ssh_ch8_ex5 里作者还特意把旧写法用注释保留在旁边，方便对照。

跑起来

动手 · 启动第一个 Boot 应用

cd ssh_ch7_ex1
./mvnw spring-boot:run

# 看到这行说明成功：
#   Tomcat started on port 8080 (http) with context path '/'
# 然后浏览器打开 http://localhost:8080/home

试试访问 http://localhost:8080/home.html——也能打开。因为 static/ 目录下的文件会被 Boot 直接当静态资源暴露，根本没经过 Controller。这个对比能帮你分清“静态资源”和“控制器路由”两条不同的路径。

仓库自带的测试

ssh_ch7_ex1 · MainTests.java
@SpringBootTest
class MainTests {

    @Autowired private WebApplicationContext webApplicationContext;
    private MockMvc mockMvc;

    @BeforeEach
    void setUp() {
        mockMvc = MockMvcBuilders.webAppContextSetup(webApplicationContext).build();
    }

    @Test
    void testHomePage() throws Exception {
        mockMvc.perform(get("/home"))
                .andExpect(status().isOk())
                .andExpect(view().name("home.html"));
    }
}

这段代码不用完全看懂，第 16 章会详讲。现在只需知道：MockMvc 能在不启动真实 Tomcat 的情况下模拟 HTTP 请求，所以测试跑得很快。书里这一章没有测试代码，是仓库补的。

本章自测

Spring Boot 是怎么“猜”到我要用 Tomcat 的？

自动配置类里写满了条件判断，形如“如果 classpath 上存在 org.apache.catalina.startup.Tomcat 这个类，并且用户没有自己定义 ServletWebServerFactory bean，就注册一个 Tomcat 工厂”。因为 spring-boot-starter-webmvc 传递引入了 tomcat-embed-core，条件成立。想换 Jetty，就在依赖里排除 Tomcat 再加 Jetty starter——条件判断自然会走向另一条分支。

为什么控制器方法返回的字符串会变成一个页面？

因为 @Controller（不带 @ResponseBody）的返回值被当作视图名处理：DispatcherServlet 拿着这个名字去问视图解析器“哪个文件对应它”，找到后渲染成 HTML 写进响应。如果类上是 @RestController，返回值则直接被当成响应体写出去——这正是第 10 章的主题。

spring-boot-starter-web 和 spring-boot-starter-webmvc 能混用吗？

在 Boot 4 里两者都还能解析，但含义已经收敛：-webmvc 明确表示传统的 Servlet 阻塞式 Web 栈。仓库统一用 -webmvc，你自己新建工程时（比如从 start.spring.io 生成）也会拿到这个名字。书里的 -web 写法照抄到 Boot 4 工程里通常能跑，但不是现在的推荐写法。
